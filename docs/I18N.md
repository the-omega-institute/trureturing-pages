# Interface languages

The public site defaults to English. `assets/i18n.mjs` provides an English / 中文
selector in the shared header. A supported `?lang=` parameter takes precedence
over the saved browser preference; otherwise the preference or English is used.
There is no automatic locale selection from the browser's system language.

The initial Chinese dictionary covers shared navigation, selected interface
labels and the complete curated Millennium research maps, including the 93 RH
formulations. Other authored prose falls back to English. Source excerpts,
Lean code, mathematical identifiers, evidence receipts, API records and user
notes keep their original content. This is interface localization, not a claim
that all research papers or the entire upstream corpus have been translated.

Use canonical English in HTML and JSON. Add exact text translations to
`site/assets/locales/zh-CN.json`. For a dynamic message, use explicit placeholders:

```js
import { t, ready } from './i18n.mjs';
await ready;
const label = t('{0} specifications · {1} families', specifications, families);
element.textContent = label;
```

The shared DOM adapter translates exact text nodes and accessible labels, and
handles dynamically added UI. It never performs substring or HTML replacement.
Mark verbatim excerpts with `data-i18n-original` or `translate="no"`; code,
preformatted text, math, editable content and textareas are already excluded.
Translate graph display data before measuring or wrapping labels. The curated
Millennium data adapter explicitly limits translation to display fields and
catalogue titles; IDs, paths, status enums and source pins remain unchanged.
Never use a translated message as a storage flag or program condition.

Language switching reloads the current URL while preserving its query parameters
and hash, so graph selection, release coordinates and filters survive. Owned HTML
links carry the selected language. External links, APIs and proof downloads keep
their original URLs. Archived Wiki redirects also retain the language query.
When storage is unavailable the URL still works. If a dictionary cannot load,
the page remains usable in English with a short visible notice.

To add another language, register its code and native label in `LOCALES`, add the
corresponding JSON dictionary and run the tests below. Missing keys always fall
back to English.

Research result translations are generated downstream by
`.github/workflows/research-translations.yml`. The Pages `request-translations` job
explicitly dispatches it after a successful deployment, including bot-started
publications. This avoids relying on a further `workflow_run` event from a
`GITHUB_TOKEN`-started publication. Only this dispatch job gains `actions: write`;
the existing build/deployment jobs keep their permissions. Manual dispatch is
also available for backfills and retries.
The input is `assets/research-translation-source.v1.json`: the exact released
headline, formal title, question, answer, context, significance, method and scope.
Every item binds its source text, source dossier/scope and result kind in a digest.
The job reuses unchanged translations and processes the complete current result
set in the automatic reading order. No hand-maintained Chinese result list is used.

The translator preserves formulas, identifiers, URLs and numerals through ordered
literal placeholders. Generation also receives the complete original fields,
definitions and formulas as context. The separate fidelity request compares the
unmasked English and Chinese fields, so the reviewer can resolve mathematical
terminology and modifier order against the actual definitions. It checks
quantifiers, negation, strict bounds, conjunctions and open clauses. Rejected
output is not admitted. This review checks translation fidelity;
it does not invent mathematical results or certify historical priority.

Accepted translations and matching review/content digests are stored as one current
projection on the `pages-translations` branch. The job dispatches the existing
`rebuild_current` path. Pages pins the reviewed cache with its other public research
input, then overlays `assets/locales/research.zh-CN.v1.json` as a presentation asset.
No topology rebuild is required for a translation-only cache update. An unchanged
source set produces no translation calls or deployment loop.

Current admission requires `review.source_context: full-source.v1`. Earlier
receipts with masked formulas are retained as candidates and independently
reviewed against the complete current source. Passing candidates reuse their
translations; rejected candidates enter the bounded correction path. Candidates
whose review fails remain available for retry in the data branch, while Pages
and the browser admit only receipts with full source context. Source hashes and
ranking remain independent of this review migration.

The source lexer distinguishes joining hyphens in numbered English modifiers
(`order-812`, `width-3`, `rank-1`) from negative values. These modifiers retain
positive numeric literals, while genuine minus signs, mathematical variables and
verbatim code/math spans keep their original protection. Cached entries are
rechecked against the source literals; incompatible receipts return to the
candidate pool for correction and independent review.

Plain English clauses in simple TeX `\text{...}` nodes are translated while the
surrounding formula remains protected in ordered pieces. Identifiers, variable
names, nested TeX and symbolic text nodes remain verbatim. The independent
review still receives the complete original and translated formulas.

Interrupted provider streams receive bounded retries with fresh response state.
An exhausted transport failure keeps the affected text pending while other accepted
results remain publishable. Literal-preservation retries receive the rejected
candidate and the exact required placeholder sequence; admission still requires
the same literal checks and independent fidelity review.

The browser matches the exact source digest, verifies the reviewed content digest,
and renders text/code/math nodes without accepting model-generated HTML. Chinese
search includes every accepted entry; math rendering follows visible results and
expanded disclosures. Missing, failed or stale translations leave the original
text available. Lean code and the full verification records keep their source text.
The translation cache never affects assessment, eligibility or result order.

The workflow uses `RESEARCH_TRANSLATION_API_KEY`, a dedicated proxy-only key for the
existing Chrono model gateway, in Actions secrets. It is never shipped to the site.
`lib.research_translations` contains the versioned translation/review prompts and
transport. Internal synchronization JSON does not modify locale assets or expose a
public status page.
